# Self-hosted map

The game, the answer map and the Filament picker draw an OpenStreetMap vector map that is served
entirely by HistoryGuessr. At runtime the browser talks to no map service other than our own origin.

```
browser ──► nginx /maps/tiles/osm/…   ──► maps (VersaTiles) ──► data/current.versatiles
        └─► nginx /maps/assets/{glyphs,sprites}/… ──► maps ──► assets/
MapLibre GL JS + style: part of the frontend bundle (resources/js/config/map-style.json)
```

| Piece | Where | In Git |
|---|---|---|
| Tiles (Shortbread schema, OSM) | `data/<snapshot>.z0-<N>.versatiles`, active one via `data/current.versatiles` symlink | no |
| Glyphs (Noto Sans), sprites | `assets/glyphs`, `assets/sprites` | no |
| Pinned versions + checksums | `versions.env` | yes |
| Tile server image | `docker-compose.yml`, service `maps` (tag + digest) | yes |
| Style | `resources/js/config/map-style.json`, generated by `scripts/maps/build-style.mjs` | yes |
| nginx proxy, cache, logs | `docker/nginx/default.conf` | yes |

## Commands

| Command | What it does |
|---|---|
| `make maps` | Fetch glyphs/sprites, build the zoom 0–8 dev tileset, activate it (`MAX_ZOOM=10 make maps` for another zoom) |
| `make maps-smoke` | Check TileJSON, tiles, glyphs, sprites and headers through nginx |
| `make maps-style` | Regenerate the style after bumping `@versatiles/style` |
| `docker/maps/scripts/fetch-tiles.sh <max-zoom> [--verify-full]` | Build a tileset from the pinned snapshot |
| `docker/maps/scripts/switch.sh <file> [base-url]` | Activate a tileset (restart, cache purge, smoke test, automatic rollback on failure) |
| `docker/maps/scripts/rollback.sh [base-url]` | Switch back to `previous.versatiles` |

Tests (`make test`) never need map data. Without data the map shows "Карта не загрузилась" and nothing else breaks.

## Sizes

Measured, not estimated. Planet, snapshot `osm.20260608`:

| Zoom | Size | Use |
|---|---|---|
| 0–8 | 314 MB | local development |
| 0–10 | _measure before deploy_ | production candidate |
| 0–12 | _measure before deploy_ | production candidate (client `maxZoom` is 12) |

Before choosing for production, build both candidates, place points in the game and in the admin picker
on each, and keep the smallest that is comfortable. Fill in the table and set `maxZoom` in
`resources/js/config/map.ts` if it is not 12 (MapLibre overzooms the last level the data has).

Disk: room for **three** tilesets at once — current, previous (instant rollback) and the one being built.
`fetch-tiles.sh` refuses to start below a free-space threshold (`MIN_FREE_GB` overrides it).

## Integrity of the data

The published SHA-256 on download.versatiles.org covers the full planet file only (~66 GB). By default
`fetch-tiles.sh` extracts the zoom range straight from the dated snapshot over HTTPS (range requests, no
full download), then runs `versatiles probe` and records our own SHA-256, the snapshot and the zoom in
`<file>.manifest`. With `--verify-full` it downloads the whole planet, verifies the published checksum,
extracts locally and deletes the planet file (needs ~80 GB extra for a while).

## Updating the data (monthly or quarterly)

1. Pick a newer dated snapshot from https://download.versatiles.org and set `OSM_SNAPSHOT` in `versions.env`.
2. `docker/maps/scripts/fetch-tiles.sh 12` (production zoom) — writes a new file next to the current one.
3. `docker/maps/scripts/switch.sh osm.<date>.z0-12.versatiles https://<site>` — restarts `maps`, purges
   nginx's map cache, runs the smoke test and restores the previous tileset if it fails.
4. Check the site by hand (labels, game round, admin picker).
5. Keep `previous.versatiles` until the next successful update. Delete older files by hand; never delete
   the targets of `current` or `previous`.

A failed update never touches the current file. Rolling back the data (`rollback.sh`) and rolling back the
application (Git) are independent.

## Updating software

- **Tile server**: change tag and digest of `maps` in `docker-compose.yml`, then `make maps-smoke`.
- **Style / sprites**: bump `@versatiles/style` (exact version) and `SPRITES_URL`/`SPRITES_SHA256` together,
  run `make maps-style` and `fetch-assets.sh`, review the style diff, run `npm run test`.
- **Fonts**: `FONTS_URL`/`FONTS_SHA256`. The style uses `noto_sans_regular` and `noto_sans_bold`.
- **MapLibre**: npm dependency; its worker is bundled as a `.mjs` asset (nginx serves `/build/*.mjs` as JavaScript).

## Backups

Back up `versions.env`, the manifests in `data/`, the style and the scripts (all but the manifests are in
Git). The tile files themselves can always be rebuilt from the public snapshot.

## Licence and attribution

The data is © OpenStreetMap contributors under the ODbL; the tiles are built by VersaTiles from it.

- Every map shows `© OpenStreetMap contributors` with a link to https://www.openstreetmap.org/copyright
  (style source attribution + MapLibre attribution control, never hidden by CSS).
- We publicly use a derivative database (a zoom-limited extract). ODbL §4.6 is met by pointing to the
  source: the exact snapshot URL is recorded in `versions.env` and in each `<file>.manifest`; this README
  documents how the extract is produced.
- Labels use `name_en` with a fallback to the local `name`; there is no transliteration. Places without an
  English name in OSM show their local name.
